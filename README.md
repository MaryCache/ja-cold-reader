# ja-cold-reader

日本語の説明文を、人に見せる前に仕上げるための[Claude Code](https://code.claude.com/)のスキルが2つ入っています。
README・解説・報告・DiscordやQiitaへの投稿・質問への返事のような、人に読ませる説明に使います。

| スキル | すること |
|---|---|
| `cold-reader` | 書き上げた文章を、書き手の文脈を持たないサブエージェントに読ませ、文脈が無いと読めない箇所を見つけて直す |
| `line-layout` | 文ごとに改行し、1つの役割を持つ文の塊ごとに空行を入れる |

段落の組み立てや言い回しの書き直しを済ませた後、出す直前に`line-layout`、`cold-reader`の順に通します。

## cold-reader

書き手は文脈を持っているので、文脈が無いと読めない箇所が自分では見えません。
こうした箇所は、たいてい人のレビューで初めて見つかります。
`cold-reader`は、その役を先にサブエージェントにやらせます。
読み手に渡すのは、本文と「誰が読み、その人が何を知っているか」の1行だけです。

読み手が探すのは、次の6つの型だけです。

| 型 | 例 |
|---|---|
| 指すものが決まらない | 「保管庫はNASです」（保管庫の実体がNASのどこか分からない） |
| 呼び名の言い直し・その場の造語 | 「サーバーの外に置いた控え」 |
| 質問や題から借りた言葉を、中身を書かずに使う | 「詰むことへの対策」（何が起きると詰むのかが無い） |
| 誰も言っていないことの否定 | 「台数ではなく」 |
| 最後の段落で前の段落を言い直す | 新しい点が1つしかない、まとめの段落 |
| 誰の・どこでの話かが抜けて、一般論に読める | 「私の環境では」が無い |

文体・語尾・翻訳調・比喩は対象にしません。

書き手は指摘を1件ずつ、直すか、直さない理由を書きます。
直さない理由には、読み手がそれを知っている根拠を名指しします（「質問の〜という文から分かる」など）。
「読み手がそう思いそうだから」のような、後から作った理由では指摘を通しません。

最後の段落の言い直しは、語の重なりを数えるスクリプト（`scripts/restate_check.py`）でも確かめます。
同じ内容を別の言葉で言い直した段落は拾えないので、これは補助です。

### 効き目

Discordでの技術的な質問1つと、答えに使う事実のメモを材料に下書きを4本書かせ、`cold-reader`の有り無しで2本ずつに分けました。
どちらの条件で書かれたかを伏せた判定役が、6つの型の失敗を数えました。

| 条件 | 失敗の数 |
|---|---|
| 無し | 4件・7件 |
| 有り | 1件・0件 |

各条件2本ずつなので、数として言えることは限られます。

## line-layout

句点で文が終わったら改行し、1行に1文にします。
主張・理由・具体・条件のように役割が変わるところで、空行を入れます。
文の中身は変えず、並べ方だけを扱います。

文ごとの改行は`scripts/layout.py --fix`で機械的に入れられます。
空行は役割を読まないと決められないので、書き手が入れます。

GitHubのように1行の改行が空白として表示される場所では、見た目の区切りは空行で作ります。
DiscordやQiitaでは、1行の改行がそのまま出ます。

## 入れ方

[skills](https://www.npmjs.com/package/skills)のCLIで入れます。

```bash
npx skills add MaryCache/ja-cold-reader -g -s cold-reader -s line-layout
```

片方だけ入れるときは、要らないほうの`-s`を外します。
スクリプトはPythonの標準ライブラリだけで動きます。

## テスト

```bash
python3 -m unittest discover -s skills/cold-reader/tests
python3 -m unittest discover -s skills/line-layout/tests
```
