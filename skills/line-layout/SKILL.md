# line-layout（改行と空行）

文の中身は前の工程（段落の組み立て・文の規範・読みやすさの書き直し）で決める。
この工程は、決まった文を**どう並べるか**だけを扱う。

長い文の後に改行せず次の文を続けると読みにくい。
主張・理由・具体が1行に並んだ段落では、読み手はどこで役割が変わるかを自分で探すことになる。

## 決まり

### 1. 文ごとに改行する

句点（「。」「！」「？」）で文が終わったら改行する。
1行に1文。

- かぎかっこの中の句点では切らない（「保管庫です。」と書いた）。
- 文を丸ごと包む丸かっこ（（補足です。））は、閉じかっこの後で切る。
- インラインコードの中では切らない。
- 箇条書きの項目・表・見出し・コードブロックの中は改行しない。箇条書きの項目の中で改行すると、Discord では項目の外に出たように見え、Markdown では続きの行の字下げが要る。1項目に2文以上が要るなら、文を短くするか、地の文の段落にする。

### 2. 役割の塊ごとに空行を入れる

空行で区切る単位は「1つの役割を持つ文の塊」。
段落より細かくてよい。
役割の例:

- 主張（何をしているか・何が言いたいか）
- 理由・仕組み（なぜそうなるか）
- 具体（どこに・何を・どの数で）
- 条件・例外（どんなときに違うか）

塊の中の文は、同じ役割を続けて説明する文だけにする。
役割が変わったら空行を入れる。

空行で分けても、塊どうしの関係（理由・具体化・対比）は文の中で示す。
空行は「役割が変わる」ことしか伝えない。
「そのため」「具体的には」のような関係を示す語を、空行の代わりに削らない。

1塊が1文になることもある。
見出しの直後に1文だけの塊が続いてもよい。

## 手順

パスはこの SKILL.md があるディレクトリから見たもの。

1. 書き上げた本文に `python3 scripts/layout.py <file> --fix` をかけ、文ごとに改行する。
2. 同じスクリプトが「段落に N 文ある」と知らせた段落を読み、役割ごとに空行を入れる。知らせが無い段落も、役割が2つ以上混ざっていれば分ける。
3. 空行を入れた結果、1塊の主張が前後とつながらなくなったら、つなぎを文で補う（段落の組み立てに戻る）。

## 表示の注意

GitHub など、Markdown の1行の改行が空白1つとして表示される場所では、文ごとの改行は見た目に出ない。
そこで見た目の区切りを作るのは空行（段落）だけなので、役割の塊の空行で分ける。
Discord や Qiita では1行の改行がそのまま出るので、文ごとの改行もそのまま見える。

## スクリプトとテスト

- `scripts/layout.py` — 検査（違反は終了コード 1）と `--fix`（文ごとの改行だけを機械で入れる。空行は入れない）。
- `tests/test_layout.py` — `python3 -m unittest discover -s tests`
